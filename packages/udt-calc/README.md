# UDT Calculation Engine

Рабочий Python-пакет расчётного ядра проекта **UDT / Universal Digital Twin**.

Предназначен для аналитических расчётов по ациклическим производственным графам, проверки входных данных, оценки ограничений мощности, анализа критического пути, поиска кандидатов в узкие места и сравнения параметрических сценариев. **Не является** событийным симулятором, MES/ERP или моделью точного выпуска за короткую смену.

## Требования

- Python >= 3.11
- Pydantic >= 2.7, < 3
- NetworkX >= 3.2, < 4
- pytest (для тестов)
- FastAPI — опционально (пример интеграции)

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\\Scripts\\activate
pip install -e '.[test,api]'
pytest -q
python examples/run_example.py
```

Если зависимости уже установлены, можно запустить без установки в режиме исходников:

```bash
PYTHONPATH=src pytest -q
PYTHONPATH=src python examples/run_example.py
```

## Что реализовано

| Область | Реализация | Примечание |
|---|---|---|
| Pydantic v2-контракты | `contracts.py` | Валидация типов, неотрицательности, неизменяемые контракты (`tuple` для коллекций) |
| KPI | `metrics.py` | Такт, эффективный цикл, фактический throughput, загрузка, простой/доступность, качество, изменение НЗП, себестоимость, прибыль, добавленная стоимость |
| Проверка графа | `graph.py` | NetworkX DAG, несуществующие узлы/ресурсы, дубли, циклы, неподтверждённые связи |
| Мощность | `engine.py` | Непрерывная верхняя оценка по операциям и общим ресурсам, пересчёт в эквивалент готового изделия |
| Критический путь | `engine.py` | Предшествования по материальным связям, точки объединения, явные ожидания и перемещения |
| Узкие места | `engine.py` | BOT-01, BOT-03, BOT-04; сохраняются несколько равных ограничений |
| Сценарии | `scenarios.py` | Разрешённые изменения, хеш исходных/новых моделей, сравнение, неизменность базы |
| FastAPI | `api.py` | `create_router()` с POST `/analyze` и `/compare` |
| Приёмочные тесты | `tests/` | 26 спецификационных CALC-кейсов плюс дополнительные негативные/интеграционные |

## Два разных расчёта

**Производственная мощность** — непрерывная оценка сверху, например `1200 / 171 ≈ 7,02`. Она **не утверждает**, что вся линия реально выпустит 7 изделий: реальные партии, пуск, ожидания и расписание ресурсов ещё не смоделированы.

**Время первого прохождения** — путь до целевого узла, где все обязательные предшественники в точке соединения должны быть готовы. В расчёт входят время обработки, транспортировки и ожидания, если они **явно заданы**. Это не точное ВПП при неизвестной логистике или конкуренции за ресурс.

Если параллельные ветви используют общий ресурс, критический путь помечается `unavailable`, поскольку требуется расписание. При `optimistic_lead_time=True` можно получить **оптимистическую нижнюю оценку**, но не точное время завершения.

## Происхождение и пропуски данных

`Amount` требует `value`, `unit`, `source`: тип (`measured`, `normative`, `synthetic_test_fixture`, `synthetic_scenario` и др.), ссылку и признак подтверждения. Измерений без источника не создаём.

`None` означает неизвестное значение. Ядро **не подставляет нули** вместо отсутствующего времени, расстояния, цены, выхода или ожидания. Исключение — **явно переданный 0** из синтетического теста либо подтверждённого измерения.

В `RawStandard` можно записать норматив `170` с `unit=None`: это сохраняет исходный документ, но запрещает использовать число как 170 секунд до подтверждения единиц и базы времени. В файле `examples/factory_confirmed.json` есть фактические сведения **только из исходных документов**, без подмены отсутствующих замеров.

`Metric` содержит `value`, `status` (`calculated`, `estimated`, `unavailable`), `kind`, `sources`, `reasons`. При отсутствии данных KPI вычисляется независимо от остальных: например, недостаточность стоимости не мешает такту.

Сырые целые счётчики без привязанного источника не маркируются как полностью подтверждённые наблюдения. Для реальных публикаций KPI привязывать счётчики к записям приёмки/смены на уровне FastAPI/PostgreSQL.

## Сценарии

```python
from udt_calc import Scenario, Override, apply_scenario, compare_scenario

scenario = Scenario(
    id="what-if-1",
    base_model_id=model.id,
    overrides=[Override(
        target_type="node",
        target_id="operation-8",
        field="processing_seconds",
        new_value=110,
        reason="СИНТЕТИЧЕСКАЯ проверка гипотезы, НЕ факт производства",
    )]
)
comparison = compare_scenario(model, scenario)
```

**110 секунд здесь — вымышленный сценарный параметр, а не измерение**. Изменения применяются только к новой модели, исходные данные сохраняются; сравнение включает хеши. Для структурных изменений производственного графа создавать новую версию модели.

## FastAPI интеграция

```python
from fastapi import FastAPI
from udt_calc.api import create_router

app = FastAPI(title="UDT API")
app.include_router(create_router())
```

Эндпоинты принимают Pydantic-модель графа и возвращают анализ. Пример специально не включает авторизацию, БД, миграции, логирование бизнес-событий и долговременное хранение `CalculationRun`. Их нужно добавить на следующем шаге приложения; непосредственно публично развертывать этот пример без аутентификации и ограничений нагрузки нельзя.

## Примеры

- `examples/run_example.py` — исполняемый **искусственный** граф с параллельными ветвями. Данные помечены `synthetic_test_fixture`.
- `examples/factory_confirmed.json` — **подтверждённые исходные сведения** из общего описания и рабочего стандарта РМ №8, причём время без единицы остаётся `null` и не применяется как фактический цикл.

## Известные ограничения (осознанно не реализованы)

1. Общая событийная симуляция (SimPy) и очереди в реальном времени.
2. Полноценное календарное расписание общих ресурсов, смен и партий; критический путь без конкуренции — нижняя оценка.
3. Прогноз **целочисленного выпуска всей линии за смену**, особенно при начальном НЗП и ограничении партий.
4. Моделирование случайных отказов, брака и повторных циклов доработки.
5. Автоматическая оптимизация и рекомендации; текущий модуль только анализирует.
6. Сложные материальные балансы с выбором альтернативного маршрута/субституцией деталей.
7. Persisted history: сохранение результатов в PostgreSQL ещё нужно реализовать на API-слое.
8. Различие некоторых специальных формул KPI (в т.ч. учебного денежного НЗП): согласование методики с заказчиком в спецификации следующего шага.

## Примечание по источникам

«Фабрика процессов» задаёт смену 20 минут, план 10 шт., заданный такт 120 с, транспортную партию 2. В рабочем стандарте РМ №8 указаны числовые значения 170 и 1, однако колонка «Время» не содержит подтверждённой единицы. Они сохраняются как исходные значения, не как измеренная длительность в секундах.

В учебном финансовом примере: 140 тыс. выручки и 573 тыс. затрат **−433 тыс. прибыли**
